6. ## Phase 3: local private Likes

The early foundation gate above passed before Phase 3 began. Phase 3 adds only Glimpse files and new Glimpse tests. Existing source still has only the exact two approved navigation additions. No existing storage adapter, Account, Cloud domain, PortableProfileV3, shared package or Desktop schema is changed.

The local namespace is a separate MMKV instance, `orion.mobile.glimpse.metadata.v1`, containing the versioned `likes` metadata document. Its records are keyed by canonical reel ID and carry schemaVersion, updatedAt, revision, removal tombstone and the minimum reel metadata for the Liked tab. Removals keep identity/revision/time but drop reel metadata. No media is downloaded by Likes. No network, account or sync operation is part of a local Like.

Like/unlike writes the complete document synchronously before notifying the UI. Repeated same-state actions are idempotent, and failed writes do not publish false state. Restart restores saved records and tombstones. Unknown versions/corrupt bytes remain untouched and disable Likes honestly. Local revisions advance past the persisted document, and updatedAt remains monotonic even during clock rollback. Snapshot data is immutable.

Merge uses a deterministic total order per canonical ID: updatedAt, revision, removal winning exact ties, then canonical metadata bytes. It is commutative, associative and idempotent. The merged document retains the greatest local revision. This is a local metadata contract; cross-platform Cloud adoption and PortableProfileV3 remain deliberate later decisions.

Liked is populated from local metadata and uses the same single-owner media surface, offline messaging, canonical Detail handoff and theme/motion/performance policies. Discover and Liked retain separate canonical positions; removing the selected Like settles to a remaining neighbor. Like/unlike stays enabled offline when local storage is available. Ordinary production exposure remains closed.

Implementation references: installed MMKV v4 factory/types plus [official MMKV documentation](https://github.com/margelo/react-native-mmkv). No dependency or native storage configuration changes were necessary.
