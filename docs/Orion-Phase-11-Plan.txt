D. SEEK SCRUBBING RECONCILIATION — CINEMA + MUSIC

This is an explicit P11.4 requirement.

Current observed issue:
- Live timing is correct.
- Final seek destination is correct.
- While finger is actively dragging/holding a seek position, incoming
  authoritative telemetry can temporarily move the thumb away from the user's
  selected position before it settles.

Required model:

NORMAL:
Desktop authoritative telemetry owns displayed progress.

ACTIVE SCRUB:
Local Mobile scrub position owns the thumb and displayed target time.

During active scrub:
- Incoming telemetry may continue to be received.
- It must not visually fight the user's finger.
- The progress thumb must not oscillate because of stale snapshots.

SEEK COMMIT:
- Bound/coalesce seek traffic.
- Commit the final intended seek target.
- Avoid flooding Desktop with unnecessary seek events.

POST-SEEK RECONCILIATION:
- Ignore/reconcile stale telemetry generated before the committed seek.
- When authoritative Desktop telemetry confirms the new playback position,
  return ownership smoothly to normal live telemetry.
- No target -> old position -> target visual bounce.
- Backward movement remains valid after a genuine user seek or legitimate
  playback-state change.

Apply to:
- Music Planet.
- Cinema sources where authoritative playback timing exists.

Do not fabricate timing for provider-only sources.
