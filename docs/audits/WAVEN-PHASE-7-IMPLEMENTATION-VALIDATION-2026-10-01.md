## Architecture and data

`apps/waven/src/features/library/localLibrary.ts` is the only durable Library repository. Native product storage is one app-private `react-native-mmkv` instance (`waven.library`); web uses localStorage. Storage failure reports unavailable and preserves existing data rather than silently using memory. The native Media3 service remains the only playback owner, with its existing stable queue recovery record. `playbackHistory.ts` only observes meaningful native `playing` events, confirms recovered queue intent and original queue-owner fingerprint, and records canonical metadata. A legacy/unattributed queue cannot be adopted by the current account. Streaming leases, headers, URLs and native queue handles do not enter Library storage.

Schema **version 2** stores `{scope, revision, favorites, playlists, history, preferences, historyReceipt}`. Identities use `[kind, source.provider, source.id]`, never display title or artist. Favorites support Track, Album and Artist, dedupe and sort by persisted timestamp/key. Playlists have stable local IDs, title, timestamps, canonical ordered Tracks, duplicate protection, create/rename/delete/add/remove/move operations, and explicit delete confirmation. History retains the most recent **200** distinct tracks with playedAt and playCount; a durable occurrence receipt prevents duplicate progress/restart/resume writes. A new A→B→A occurrence increments A; a failed resolve, tap, buffering, paused state or never-started item does not write. History recording can be paused or cleared in the Library. Home Recently Played takes the first five entries from this repository and truthfully stays empty before a real play.

Active state is capped at **2 MiB UTF-8 per scope**, with 5,000 favorites, 100 playlists and 1,000 songs per playlist. New repair backups use four fixed original-preserving slots with an **8 MiB** combined budget; exhaustion blocks repair before overwrite. The previous verified state is retained for ordinary mutations. Existing older recovery copies are preserved. v1 flat liked entities and named playlists migrate to v2 with canonical identity and track order, preserving the exact original before normalization. Damaged/wrong-scope data is backed up before previous-state recovery; future schema versions remain read-only. All published changes require storage read-back; a failed write rolls back or leaves the prior verified copy. No normal migration wipes data.

Scopes are `local` or `google:${encodeURIComponent(accountId)}` from the already accepted Google session's canonical account ID. Anonymous data does not auto-merge into Google state. Scope switches close pending UI actions and cancel stale playback handoffs; history additionally checks the original queue owner. The controlled native fixture uses a separate MMKV instance (`waven.library.validation`) and distinct synthetic A/B account IDs; it never changes product Library, session, SecureStore or Orion Cloud. Product account switching with two interactive Google chooser identities was not claimed in this checkpoint; unit/runtime identity tests and the native separate-namespace fixture are the evidence used. An app-private unencrypted local history policy, the UI's pause/clear controls, export/deletion semantics and provider terms require explicit review before any future Cloud sync or distributed privacy acceptance.
