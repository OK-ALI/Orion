## Read-only Orion Mobile trace

`apps/mobile/app/_layout.tsx` mounts `NetworkProvider`. `src/context/NetworkContext.tsx` subscribes to NetInfo (lines 122–137), retains transport plus internet reachability, then runs a bounded eight-second TMDB `/configuration` probe and a 15-second timer (lines 141–298). `networkStatePolicy.ts` distinguishes no transport/internet from a failed remote service, emits a recovery epoch only when returning to online, and exposes remote readiness. This distinguishes mobile data from Wi-Fi loss but does not provide WAVEN's required four-state, AppState-aware, serialized recovery owner. The probe is Cinema-specific.

On loss, `MyListSteadyStateSync.tsx:181` exits before Drive access when offline; local Library storage remains usable. Its latest-state/account checks, busy flag, pending mode, signatures/checkpoints and serialized `portableProfileCloudTransactionCoordinator.ts` prevent overlapping Cloud read/decide/write/verify/checkpoint transactions. Reconnect and policy/account/signature effects request reconciliation; an AppState-aware heartbeat is separate from the network probe. Local My List and ordering are persisted and read-back verified in `myListPersistence.ts`, independently of Cloud. Watched/viewing coordinators use the same account/transaction concepts. These are evidence for preserving local ownership and re-reading before supported Cloud reconciliation, not authorization to add music namespaces in WAVEN.

`HomeConnectionPanel.tsx` and `OfflineBanner.tsx` consume the shared network context; `HomeContinueWatching.tsx` uses `remoteReady`. `offlineArtworkPolicy.ts` implements bounded manifests but hardcodes TMDB paths and Cinema IDs; `offlineArtworkCache.ts` owns image files. `OrionOfflinePlayerSurface.tsx` and the download repository/engine consume intentional local Cinema media. They are not music streaming or WAVEN downloads. End-to-end trace: NetInfo loss → policy offline → remote consumers/Cloud coordinator stop remote work → local Library and owned downloads stay available → transport returns → Cinema service probe → online/recovery epoch → effects/serialized Cloud reconciliation re-read before merge/write/verification. Source-only trace, not new Orion physical validation. Orion source is not modified.

## Production architecture and boundaries

One lifecycle service under `src/infrastructure/connectivity` owns transport observations, independent internet verification, provider health/cooldowns, cancellation and serialized recovery. Consumers gate through it. Native Media3 is not stopped/replaced because transport changed; fresh remote resolutions are rejected with product copy while offline, and a successful return never automatically starts a new song. Current queue/recovery remains native-owned.

A versioned, bounded app-private metadata/pending-read store provides public catalogue snapshots and deduplicated refresh intent, read-back verification, corruption/future-version preservation, stale expiry and deterministic eviction. It stores canonical metadata, not audio, credentials, signed URLs, arbitrary playback sources or search history. Existing local favorites/playlists/history are the durable mutation owner; no duplicate remote music mutation or Cloud-sync queue is invented before Phase 9. Recovery validates internet, validates each service separately, then resumes eligible reads/refreshes serially. Disconnection/account change cancels stale work; cached data never becomes authoritative for stream availability or freshness.

The existing development package is the physical target. Its accepted MMKV baseline hashes were verified before changes (`678BF73F…1529A87` Library, `F8E81D0C…4A81CAE` CRC). It may be enabled only while validating and returned to disabled Personal state. Canonical package and Work profile remain untouched. `release/waven-phase8-20261002/source-before.json`, `authority-before.json` and exact `before-bytes/` preserve the current dirty boundary, including all 107 dirty preimages.
